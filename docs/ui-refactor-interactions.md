# 时间色谱 UI 重构：交互与业务映射

## 范围与依据

- 目标原型：`design-demos/time-chromatics/{today,plans,steps,timeline}.html` 及其 `time.js`、`../final/prototype.js`。
- 现有实现：`/app` 下的今日、计划、天梯、甘特四视图及必要的状态、弹层和 API。
- **现有代码是行为依据，原型是视觉/布局依据。** 下文将“代码事实”与“承接建议”分开；建议不代表已实现。
- 本轮仅静态阅读并编写本文，未启动应用、未调用真实接口、未做运行验证，未修改业务代码。

### 已确认的实现决策（2026-11-01）

1. 子任务详情弹窗增加“顺延/跳过”快捷操作，复用列表入口的 mutation、确认和撤销规则。
2. 计划卡点击改为打开目标详情弹窗；原 AI 聚焦与 `/task/[id]` 完整详情仍保留独立入口。
3. 新增计划级筛选：“查看阶梯/排期”只显示当前计划，并提供清除筛选恢复全局的入口；甘特同步支持计划筛选。
4. 甘特采用 14 天可视窗口，完整排期数据仍可横向滚动访问，不裁切现有至少 30 天或更长的数据范围。

以上均为后续实现要求，不代表现有代码已经具备。

### 共同事实

1. 四视图共用 `/app`，不是四条独立页面路由。`src/app/app/page.tsx:14-23` 仅从 `?view=plans|steps|timeline` 读取初始视图；`HomePage` 用 `currentView` 本地状态切换（`src/components/home/home-page.tsx:31-34,87-119`），导航点击不会改写 URL。
2. `HomeMainArea` 是四视图分发点（`src/components/home/home-main-area.tsx:30-149`）；`HomeWorkspace` 还挂载共享顶栏、右侧 AI 面板和快捷键脚注（`home-workspace.tsx:28-70`）。原型四页没有完整表达这些共享区域，不能在重构时默认删除。
3. 首屏通过 `GET /api/tasks?withSubtasks=1` 水化 tasks store；今日、计划、天梯、甘特均从同一快照派生（`use-home-data.ts:31-44`、`features/tasks/store.ts:33-74`）。AI 分析进入 `done` 后会刷新（`use-home-data.ts:75-95`）。
4. 相关任务和统计 API 均先执行 `requireAuth`，任务读写校验所有权或按 `userId` 查询。UI 改造不能替代服务端权限，也不能在浏览器伪造认证头。
5. 原型的数据、日期和多数按钮反馈是硬编码/本地模拟，不能视为既有业务承诺（`time-chromatics/time.js:80-151`、`design-demos/final/prototype.js:74-163`）。

## 二、交互与业务规则

### 1. 首次加载、重试与视图切换

- **入口与操作**：进入 `/app` 或带初始 `view` 的 URL；点击侧栏/移动 Tab/命令面板切换视图。
- **代码事实**：`useHomeData.loadSubtasks` 拉取任务并同时水化分析面板；账号退出或切换会清空 store，避免跨账号残留（`use-home-data.ts:46-68`）。视图切换只改本地状态，不请求新接口。
- **反馈**：今日有 `ListSkeleton`；四视图均有加载失败卡和重试。计划、天梯、甘特有空态。**现有缺口：后三视图没有消费 `fetching`，首次加载中没有对应骨架/加载反馈**（`home-main-area.tsx:81-145`）。
- **原型承接**：四页可改成统一顶部导航，但仍调用 `setCurrentView`，不应复制成四个独立业务页面。加载、空态、错误态需进入各自新布局；后三视图加载态若补齐，应单列为交互修正，不能写成现状。

### 2. 创建学习目标并生成 AI 计划

- **入口与操作**：今日内联输入按 Enter/“开始规划”；空输入点击会打开完整新建弹窗。侧栏、移动“新建”、快捷键 `N`、命令面板也可打开弹窗（`goal-card.tsx:37-48`、`use-home-hotkeys.ts:47-54`）。
- **校验与约束**：客户端仅接受非空 trimmed goal；服务端要求 title 非空且最多 500 字，并校验任务容量、每日新建/删除操作额度及创建频率（`api/tasks/route.ts:26-86`）。完整弹窗可编辑标签和识别 URL；取消/关闭弹窗不创建任务。
- **状态与接口**：先 `POST /api/tasks {title,tags}`，再 `POST /api/tasks/[id]/analyze {adjustment?}`。分析过程更新 `entries[].stream`，关闭仪式感弹窗只是最小化，不是取消分析（`home-overlays.tsx:119-137`）。
- **结果**：创建失败在 AI 面板生成临时错误条目，可重试创建；分析失败显示错误和“重新尝试”。成功后获取任务详情、刷新任务列表和会话，并生成服务端通知；旧计划重排会替换子任务（`use-analysis-runner.ts:13-37`、`analyze/route.ts:498-545`）。
- **现有缺口**：完整弹窗把 `selectedTags` 作为第二参数传出，但首页 `runNewGoal` 只接收 `goal`，当前该入口的标签不会继续传给 `startAnalysis`（`new-task-input.tsx:42-46`、`home-overlays.tsx:60-63`）。文档不将其描述为已生效。
- **原型承接**：内联入口可直接复用现有 `GoalCard` 行为。原型“分析中→已生成”的定时器是假反馈，必须替换为真实 phase/error/done；完整新建、额度错误和重试仍需可访问。

### 3. 今日筛选、选择任务与查看详情

- **入口与操作**：点击“全部/仅待完成”；点击任务行或按 Enter；使用上下键和空格；清除全局标签筛选。
- **代码事实**：仅待完成写入 `localStorage: gradus_today_filter_pending`；全局 `selectedTag` 同时影响今日、计划、天梯和甘特（`use-home-filters.ts:25-46,66-102`）。任务行点击同时打开详情并聚焦所属 AI 计划（`subtask-line.tsx:57-78`）。
- **反馈**：筛选无结果显示对应空态，可清除标签或展示全部；详情关闭只清 UI 状态，不写数据。AI 面板“定位子任务”会滚动并高亮现有 DOM 锚点 3 秒。
- **原型承接**：筛选按钮和任务弹窗可换视觉，但需保留真实计数、标签过滤、键盘/锚点及详情内容。原型“下一程”链接和周色条没有真实跳转/数据逻辑，不能直接当作已实现导航。

### 4. 完成或恢复子任务

- **入口与操作**：今日、后续卡、天梯、甘特复选框，详情弹窗按钮，AI 子任务行，或键盘空格。
- **约束与接口**：统一调用 `toggleSubtaskMutation`，先乐观更新，再 `PATCH /api/tasks/[taskId]/subtasks/[subtaskId] {completed}`；失败回滚并 toast。全部完成时将计划状态改为 `done`，从完成状态恢复时改为 `active`，另发计划状态 PATCH（`features/tasks/mutations.ts:61-128`）。
- **结果**：同步 tasks store、AI 面板副本和本地统计增量；可能出现鼓励 toast、里程碑或全计划完成祝贺。详情弹窗在触发后关闭。现有代码没有统一的“请求中禁用复选框”保证。
- **原型承接**：完成态、总进度和各视图必须来自同一 store，不可只切 DOM class。恢复完成同样走真实 mutation，不能做成纯视觉撤销。

### 5. 顺延一天、跳过与撤销

- **入口与操作**：未完成的今日/后续任务悬停操作；“顺延”先打开确认弹窗，“跳过”直接执行；成功 toast 提供撤销。
- **业务规则**：两者都只对当前子任务执行 `startDay + 1`，接口为 `{action:"postpone"}`；**跳过不标记完成、不增加完成数，也不会自动顺延其他子任务**（`use-subtask-actions.ts:37-74`）。撤销调用 `{action:"unpostpone"}` 做 `-1`。
- **结果**：乐观更新，失败回滚并提示；顺延弹窗在确认后关闭，取消不写数据。撤销失败恢复撤销前状态并提示（`features/tasks/mutations.ts:135-165`）。
- **原型承接**：**已确认**在子任务详情弹窗增加“顺延/跳过”快捷操作，与列表入口共用同一 mutation、确认弹窗和撤销 toast，不新增接口或第二套规则。原型把“跳过”渲染为 `done` 且写“后续计划已自动接续”，与代码冲突，不能照搬（`prototype.js:121-132`）。现有顺延弹窗“智能重排接续计划”文案也宽于实际单任务 `+1` 行为，实现时不应继续扩大承诺。

### 6. AI 修订建议与按意见重排

- **入口与操作**：选择 AI 条目；点击“定位子任务”“填入调整意见”“忽略”；在调整框输入后点击“按意见重排”。
- **代码事实**：建议由已完成计划真实数据在客户端推导，覆盖 Bloom 跨度、仅搜索资源、死链、日均负载（`ai-review-hints.ts:76-141`）。“填入”只填本地 adjustment；“忽略”只在本组件实例隐藏建议，均不直接改计划（`ai-inspector.tsx:58-64,114-137`）。
- **接口与结果**：重排复用 analyze API，adjustment 服务端 trimmed 后最多取 1000 字；受 AI 配额、频率和同任务单飞锁约束。进行中展示阶段，失败可重试，成功后刷新任务数据。原型没有取消建议的持久化语义。
- **原型承接**：两条提醒可改为时间色谱样式，但“应用/稍后”不能伪装成一键落库。建议映射为现有“填入调整意见/忽略”，真正变更仍由“按意见重排”触发；不得新增隐式 API 语义。

### 7. 计划聚焦、进入详情、新建与删除

- **入口与操作**：点击计划卡、点击“进入详情”、新增目标或删除。
- **代码事实**：卡片点击仅 `focusTask`；详情按钮跳转 `/task/[id]`；新建打开完整弹窗（`home-main-area.tsx:92-103`）。计划进度来自子任务完成数，状态显示已规划/进行中/已完结（`plan-card.tsx:27-39`）。
- **删除约束与结果**：删除需二次确认，受所有权、频率和每日新建+删除操作额度约束；请求中禁用确认/取消及关闭。成功后才移除 store 和 AI 条目，失败保留确认目标并 toast，取消无请求（`use-subtask-actions.ts:76-99`、`delete-plan-modal.tsx`）。
- **原型承接**：**已确认**计划卡点击打开目标详情弹窗，展示当前计划的真实数据；弹窗需提供“聚焦 AI”和进入 `/task/[id]` 的明确入口，不能用原型的简化内容替代完整详情页。现有删除及二次确认必须保留，删除等内部按钮不得冒泡触发卡片弹窗。**已确认**“查看阶梯/查看排期”新增计划级过滤，不再只是全局页链接；筛选仅影响前端视图，不改变服务端数据。

### 8. 天梯层级筛选与任务操作

- **入口与操作**：点击六级卡筛选，再点同一层或“显示全部”恢复；点击复选框或任务卡。
- **代码事实**：`selectedBloomLevel` 是视图本地状态；缺省 Bloom 按 L1 处理，总数和百分比由当前传入子任务计算（`ascending-steps-view.tsx:23-37`）。完成和详情分别复用第 4、3 节流程。
- **反馈**：各层显示完成数/总数和进度，全部为空时显示创建引导；没有针对“筛选后该层为零”的专门空态。
- **原型承接**：六色台阶、层级说明和清单可重排，但计数需基于真实 `levelGroupsOf`。**已确认**新增计划级筛选：从计划卡“查看阶梯”进入时只显示该计划，层级计数和总进度均基于筛选后的真实子任务；清除计划筛选恢复全局，且可与现有 Bloom 层级、全局标签筛选组合。原型总进度会随模拟勾选即时变化，实现中应由真实 store 更新驱动。

### 9. 甘特浏览、色条详情与完成

- **入口与操作**：拖动空白区域、触屏横滑或聚焦后使用左右键；点击任务标签/色条；点击复选框。
- **代码事实**：有日期任务排在先，无日期任务在后并显示“排期未定”；窗口从最早开始日起，覆盖完整排期且至少 30 天（`timeline-window.ts:1-8`）。当前表头显示 D1…Dn，短日期在 title 中；今天仅在实际落入窗口时高亮。
- **接口与反馈**：浏览和布局不调用接口；详情和完成复用既有流程。空数据显示“暂无时间轴数据”，加载失败可重试；没有计划筛选和周期切换状态。
- **原型承接**：**已确认**采用 14 天可视窗口、真实日期表头和今日色纹；完整数据范围仍按 `timeline-window.ts` 计算，超出 14 天的任务通过现有横向滚动访问，不裁切数据。**已确认**新增计划筛选，筛选只改变当前前端展示，清除后恢复全部计划。原型周/月按钮仅换选中态，前后周期只改标签且保留旧色条，均不是可迁移业务实现（`time.js:138-151`）。

## 三、组件与接口对应

### 组件处理建议

| 处理方式 | 组件/区域 | 必要建议 |
|---|---|---|
| 直接复用行为与数据契约 | `useHomeData`、tasks/stats store、`useHomeFilters`、`useSubtaskActions`、`useHomeTaskToggle`、`useAnalysisPanel` | 不因视觉重构复制数据源或另写 mutation。 |
| 直接复用功能，调整外观 | `GoalCard`、`NewTaskInput`、`PostponeDialog`、`DeletePlanModal`、`RightPanel`/`AiInspector` | 保留校验、真实资源、错误/取消和弹层层级；不要换成原型的简化假弹窗。 |
| 复用并扩展既有交互 | `SubtaskDetailModal`、`PlanCard`、`useHomeFilters` | 详情弹窗新增顺延/跳过但复用统一 actions；计划卡改为打开目标详情，并保留 AI 聚焦和完整详情入口；计划筛选扩展现有前端过滤状态，不新增接口。 |
| 调整布局/样式 | `TodayView`、`TodayTaskList`、`SubtaskLine`、`LaterSchedule`、`AllPlansView`、`AscendingStepsView`、`StepLevelTile`、`StepsSubtaskCard`、`TimelineView`、`TimelineGanttRow` | 以时间色谱重排，但保留必要 props、DOM 锚点和事件入口；Bloom 色映射需统一来源。 |
| 调整共享外壳 | `IconRail`、`SideNav`、`MobileTabBar`、`AppHeader`、`HomeWorkspace` | 新顶部导航需等价承接现有新建、搜索、通知、主题、用户和 AI 入口，避免只在今日页可见。 |
| 需要新建/拆分的展示组件 | 今日七日摘要、目标详情弹窗、计划筛选工具栏、计划统计摘要、天梯层级说明、甘特工具栏/图例 | 目标详情复用当前计划真实数据并承接现有入口；筛选工具栏只操作前端状态。其余新增区域只接收真实派生数据，不在组件内新增取数或业务规则。 |
| 暂不按原型实现 | AI 一键应用、跳过=完成、固定 14 天数据裁切、周/月假切换、只改标签的周期按钮 | 这些不是单纯视觉组件，属于错误模拟或未获确认的新业务能力。 |

### 现有接口与调用时机

| 接口 | 关键输入/输出 | 调用时机与消费者 |
|---|---|---|
| `GET /api/tasks?withSubtasks=1` | 返回当前用户计划及子任务 | 首屏、重试、AI 完成后的刷新；`getTasksWithSubtasks`。 |
| `POST /api/tasks` | `{title,tags}` → Task；title 非空且 ≤500 字，受容量/额度/限流 | 新目标确认后、AI 分析前；`createTask`。 |
| `GET /api/tasks/[id]` | 返回单计划及子任务；非本人 404 | AI 成功后获取详情；计划“进入详情”的相关数据基础。 |
| `POST /api/tasks/[id]/analyze` | `{adjustment?}` → `{ok,result:{subtasks,totalDays,startDate,...}}`；受 AI 配额、限流和单飞锁 | 创建后生成、错误重试、按意见重排；只能在服务端调用 AI。 |
| `PATCH /api/tasks/[id]/subtasks/[subtaskId]` | `{completed}` 或 `{action:"postpone"|"unpostpone"}` | 完成/恢复、顺延/跳过、撤销；统一 mutations。 |
| `PATCH /api/tasks/[id]` | `{status:"active"|"done"}` 或 `{tags}` | 全部完成/恢复时级联计划状态；标签编辑。 |
| `DELETE /api/tasks/[id]` | 成功 `{ok:true}`；受操作额度和限流 | 删除计划二次确认后。 |
| `GET /api/user/stats` | `streak/todayCount/weekCount/totalCompleted/activeTaskCount/learnDays/totalGoals` | 共享 stats store 加载；今日统计与等级。打卡先本地增量。 |
