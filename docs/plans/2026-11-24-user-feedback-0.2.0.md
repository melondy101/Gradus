## 一、三条用户声音

### 声音 A · 流程实测者

**场景**：输入「两周内把英语语言学概论第一章做成 10 分钟的课堂展示，要有清晰的概念讲解和现场演示」，走完从落地页到结果的完整链路。

**认可**：
- 四段流水线（意图解析 → 资源检索 → 计划生成 → 核查修订）有明确的阶段提示、进度百分比与剩余秒数，比一个转圈强；生成过程虽慢但一直在动。
- 排序正确：先看慕课整理术语 → 搭框架 → 做单元测验 → 对比分支学科差异 → 最后落到「设计演示初稿 / 试讲演练 / 复盘定稿」，确实是从识记走到创造，没有一上来就让学生直接写稿子。
- 规模自洽：七个任务，工时合计 10 小时，排期 14 天，与「两周」对得上。
- 资源标 VERIFIED，点开确实存在。
- 天梯图是这次最喜欢的部分：六级台阶、每阶标 x/y 完成数、点台阶按层筛选、勾选后进度从 0 跳到 14%、连续学习天数变成 1 天、本周完成率 20%；奖杯式等级与「再完成几步升级初学」的小目标确实推着人往前走。

**硬伤**：
1. 免费只能生成一次。
2. 重排直接撞墙。
3. 支付在 PC 端是断的。

### 声音 B · 细节挑刺者

**认可**：整体判断——「这是在观猹上试到的最完整的一个产品」。它不是在做一个更好看的待办清单，而是把「学习」这件事的认知顺序当成了产品结构本身，天梯、甘特、流水线三块是咬合的，不是各做一个页面凑数。免费额度只够跑一次全程，反而让人觉得后面还有东西。

**硬伤**：
1. **资源已失效**：两条资源都指向中国大学 MOOC 上东北大学的《英语语言学概论》，标 VERIFIED，链接活着——但那是 2018 年第 4 次开课，页面显示「当前开课已结束」「老师已关闭该学期，无法查看」。**资源校验做了链接存活，没做课程是否还在开的判断**，这个差别对备考的人挺关键。
2. **今日面板层级标签全错**：六个子任务全部显示「L3 应用」，但详情页和天梯图里分别是 L2、L2、L3、L4、L4、L5。同一页面两套标签。阶梯标错对主打「认知阶梯」的产品挺伤，等于招牌挂歪了。
3. **免费额度没披露**：落地页通篇没提配额，进会员中心才看到：同时最多 2 个任务、今日新建加删除 10 次、**可用 AI 规划次数 0 次**。免费版实际只能生成一次计划，点「按意见重排」直接弹出「AI 规划次数已用完」。应该在落地页写明，或至少在第一次生成前提示一句「这是你的唯一一次免费规划」。
4. **购买流程断裂**：次数包只显示「AI 规划 10 次包」和「30 次包」，价格要点头进付款页才知道。点击跳的是支付宝 `alipays://` 协议，PC 浏览器直接 `ERR_UNKNOWN_URL_SCHEME`。移动端可能没事，桌面用户到这里就断了。
5. **LICENSE 缺失**：落地页底部有「开源协议」，README 挂着 MIT 徽章并指向 `./LICENSE`，但仓库根目录没有这个文件，raw 地址 404。代码是真的开出来了，Dockerfile、部署文档、开发者指南都在，就缺这一张纸。如果打算让别人自托管，这个还是补上。
6. **工时对不上**：天梯图里每个任务的工时全都显示 1.5h，和详情页里的 1.5、3、4.5 小时对不上。
7. **小错位**：会员与容量按钮第一次点没反应，以为坏了；子任务卡片点开是弹新标签页跳慕课，不是站内预览。

**建议**：演示入口「看看它怎么工作」点下去只是页内锚点跳转，并没有可交互的样例。一个人带着真实目标进来，想先看看别人生成出来长什么样，没地方看。

### 声音 C · 产品判断者

**用户画像**：
- 适合：正在自学一门技能、又总是卡在「不知道从哪一步开始」的人；备考的；想利用下班时间系统学新东西的；需要对着一篇论文或者一门网课整理路线的。
- 不适合：只想随手记个待办、不需要拆解和目标层级的。

**结论**：如果只改一件事，先修今日面板那个层级标签。那是最容易被人第一眼看到的地方，也是最能说明这个产品和别的待办有什么不同的地方。

### P0 — 本版必须修完

#### FB-01 今日面板层级标签全错

- **现象**：今日面板六个子任务全部显示「L3 应用」；详情页与天梯图显示 L2、L2、L3、L4、L4、L5。
- **根因**：线上版 `src/components/home/timeline-card.tsx` 的 `bloomLevelOf(row)` 先读 `row.urgency` 再读 `row.bloomLevel`。`urgency` 是**任务级共享分数**（`analyze/route.ts` 给同一任务的全部子任务写同一个 `urgencyScore`），于是所有子任务被压成同一层级；`bloomLevel` 只有在 `urgency` 为空时才被读到。
- **修复**：`bloomOf(row)` 作为唯一层级判定（`bloomLevel` 优先，`urgency` 仅作缺失兜底）；`steps-level-model.ts` 的分组与 `ascending-steps-view.tsx` 的筛选改用同一函数；`bloomLevel` 缺失时 UI 显示 `L?` 而不是假装 L3。
- **验收**：今日面板 / 天梯 / 详情页三处层级标签完全一致；天梯台阶层级与卡片标签一致。
- **状态**：已修（0.2.0）。核心修复随 `qoder/ui-design` 合入 main，本版完成单一真相源收口与回归测试。

#### FB-02 工时口径不统一

- **现象**：天梯图每个任务都显示 1.5h；详情页显示 1.5、3、4.5。
- **根因**：
  1. `src/lib/ai/prompts.ts:141` 的模板里硬写 `"deep_work_hours": 1.5`，模型照抄 → 全部子任务同值。
  2. `deep_work_hours` 的语义在 `prompts.ts:175` 是「每天需要的深度专注时长」，但 `subtask-line-model.ts` 的兜底分支返回 `durationDays × 1.5`（总计），单位错配。
  3. 详情页 `subtask-meta-grid.tsx` 把「每日」值标成「深工作时长 … 小时」，读起来像总计。
  4. 同一口径在 4 处重复实现（`subtask-line-model.ts`、`today-metrics.ts`、`ai-review-hints.ts`、`lib/mcp/server.ts`）。
- **修复**：新增 `src/lib/workload.ts` 作为唯一口径源（`deepHoursOf` 每日 / `totalHoursOf` 总计 / `planTotalHours`）；4 处调用点统一改用；展示层统一标注「N 天 · 每日 X h」；prompt 模板改为区间示例并加「各子任务必须差异化」约束。
- **验收**：三处展示同一口径且互不矛盾；不再出现全部 1.5h。
- **状态**：已修（0.2.0）。

#### FB-03 免费额度未披露且重排撞墙

- **现象**：会员中心显示「可用 AI 规划次数 0 次」；点「按意见重排」弹出「AI 规划次数已用完」；落地页只字未提配额。
- **根因**：`src/lib/commerce/credits.ts` 首次使用只发一条 `{source:"trial", total:1, remaining:1}` —— 终身 1 次；生成与重排走同一条通道，重排同样扣次。`src/lib/membership/tiers.ts` 却声明「每日 5 次新建 AI 规划全案拆解」，**对外表述与实现不符**。落地页七个区块中没有任何配额/价格信息。
- **修复**：试用额度扩为 3 次（含重排）；新增每日刷新额度 1 次（东八区日界）；扣减顺序 trial → 当日 daily → 付费包；`getCreditBalance` 与实际可消费对齐；失败退还链路保持不变；tiers 文案订正；落地页新增配额与价格说明；首次生成前一次性提示剩余额度。
- **验收**：新注册账号可连续生成 3 次；第 4 次被拦时提示清晰且说明如何获得额度；次日额度刷新为 1；落地页可见配额与价格。
- **状态**：已修（0.2.0）。

#### FB-04 / FB-11 桌面端支付断链与价格不透明

- **现象**：PC 浏览器点购买 → `alipays://` 协议 → `ERR_UNKNOWN_URL_SCHEME`；次数包价格需进付款页才可见。
- **根因**：`watcha-purchase-tab.tsx` 用 `window.location.assign` 跳转；`watcha-pay.ts` 的 `safeWatchaPurchaseUrl` 显式放行 `alipays:` 协议（该协议本为移动端设计）；后端已返回 `purchase.qr_code_url` 但 `api/payments/watcha/access/route.ts` 未透传；Watcha 页签未复用 `catalog.ts` 里的价格。
- **修复**：后端透传 `purchaseQrUrl`；客户端类型同步；桌面端改为二维码面板（展示二维码 + 复制链接 + 深链按钮），移动端保持直唤起；深链失败 1.5s 后回落提示；价格直接显示在次数包卡片上。
- **验收**：PC 点购买弹二维码而非报错；移动端仍能唤起支付宝；两个页签价格一致可见。
- **状态**：已修（0.2.0）。

#### FB-05 资源链接活着但课程已结课

- **现象**：资源标 VERIFIED，链接可访问，但课程「当前开课已结束」「老师已关闭该学期，无法查看」，实际无法学习。
- **根因**：`resource-validator.ts` 只发 HEAD 看状态码，200 一律判为 `ok`；全仓无任何「已结束/无法查看/已关闭」识别；`fetchers/course.ts` 的平台识别不含 icourse163；`DOMAIN_AUTHORITY` 未收录 icourse163 → 权威分恒为默认 3 分（渲染成「权威 0.3」）。
- **修复**：新增 `src/lib/resource-enrollment.ts`：平台名单（icourse163 / xuetangx / imooc / coursera / edx / bilibili）+ 通用文案兜底；名单内域名改用 GET 取正文判定；`ResourceValidation` 增加 `content_status` 与 `status_evidence`；信任标签对 ended/closed 改显「已结束 · 不可学」，详情页给出警示与替换入口；`DOMAIN_AUTHORITY` 补齐国内课程平台权重（FB-13 的一部分）。
- **验收**：指向已结课课程时资源标签显示「已结束 · 不可学」；正常在开的课程仍显示已校验。
- **状态**：已修（0.2.0）。

#### FB-06 LICENSE 文件缺失

- **现象**：README 挂着 MIT 徽章指向 `./LICENSE`，仓库根目录无此文件，raw 地址 404。
- **根因**：README 文案声明了 MIT，但许可证文件从未创建；工作区曾以「尚待维护者明确发布」措辞回避，与「开源可自托管」的产品定位冲突。
- **修复**：新建仓库根目录 `LICENSE`（MIT，`Copyright (c) 2026 拾级 Gradus contributors`）；README 恢复徽章与章节文案；页脚「开源协议」链接直达文件；PRD 同步一行说明。
- **验收**：`/LICENSE` 可访问；README 徽章可点开；页脚链接直达文件。
- **状态**：已修（0.2.0）。

### P1 — 本版修完

#### FB-07 计划生成失败且旧计划被清空

- **现象**：偶发「计划生成失败」。
- **根因**：`analyze/route.ts` 先 `deleteSubtasksByTaskId` 再 `createSubtasks`，第二步失败则任务被清空成零子任务，旧计划不可恢复；错误文案统一为「分析未能完成，请稍后重试」，用户分不清超时、模型无产出还是落库失败。
- **修复**：改为事务内原子替换（失败回滚，旧计划完整保留）；错误分级为 `AI_TIMEOUT` / `INVALID_PLAN` / `SAVE_FAILED`；前端失败时保留已完成节点并展示分级文案与重试入口；额度失败退还路径加测试锁死。
- **验收**：模拟写入失败后旧子任务仍在；失败提示可区分原因。
- **状态**：已修（0.2.0）。

#### FB-08 资源跳新标签页，无站内预览

- **现象**：子任务卡片点开直接弹新标签页跳慕课。
- **根因**：`safe-url.ts` 的 `openExternalUrl` 统一 `window.open(_blank)`，产品内没有预览层。
- **修复**：新增 `POST /api/resources/preview`（requireAuth + SSRF 校验 + 复用 `url-fetcher` 抓取，失败返回 `{ok:false}` 不阻断）；客户端请求逻辑放 `src/lib/api/resources.ts`；详情弹窗与资源行改为「点击展开站内预览（摘要 + 标签）」，「打开原链接」降为次级动作。
- **验收**：资源可在站内看到摘要与标签；原链接仍可一键打开。
- **状态**：已修（0.2.0）。

#### FB-09 演示入口只是页内锚点

- **现象**：「看看它怎么工作」点下去只是页内锚点，没有可交互的样例。
- **根因**：`hero.tsx` 的 CTA 是 `<a href="#sec-how">`，落到静态四步说明卡；落地页唯一能看成品的是「先看演示数据」→ `/app?view=plans`。
- **修复**：新增 `src/components/landing/demo-band.tsx`（静态样例数据的可点选迷你天梯，六级台阶可点、可勾选、进度可动，不请求后端）；hero CTA 改指向 `#sec-demo`；保留「先看演示数据」作为第二条路径。
- **验收**：点「看看它怎么工作」进入可交互样例，台阶可点、进度可动。
- **状态**：已修（0.2.0）。

#### FB-10 会员与容量按钮首点无响应

- **现象**：第一次点没反应，以为坏了。
- **根因**：`global-membership-modal.tsx` 用模块级全局 handler，handler 在 `useEffect` 里注册；注册前触发的点击只 `console.warn`，界面毫无反应。
- **修复**：模块级 handler 增加待处理意图队列（未注册时记下 tab，注册后立即执行并清空）；未注册时给出可见提示而非静默；抽成可测纯函数并补单测。
- **验收**：刷新后第一次点「会员与容量」即弹出。
- **状态**：已修（0.2.0）。

## 四、版本与发版纪律

### 4.1 三条版本轴

| 轴 | 真源 | 含义 | 何时变 |
|---|---|---|---|
| **产品版本** | `package.json` 的 `version` 与 `src/lib/version.ts` 的 `PRODUCT_VERSION`（二者必须相等） | Web 端产品版本，落地页徽章与页脚显示 | 每次发版 |
| **客户端版本** | `src/lib/version.ts` 的 `CURRENT_APP_VERSION` | Android/全平台客户端的 GitHub Releases 更新通道版本 | 只在发布客户端安装包时 +1 |
| **文档版本** | `docs/PRD.md` 顶部的版本行 | PRD 文档自身的版本 | PRD 发生实质改版时 |

> **易踩坑**：`CURRENT_APP_VERSION` 只在发客户端包时改动。误改它会让所有客户端弹更新提示。

### 4.2 发版清单（每次发版必须逐项完成）

1. `package.json` 的 `version`
2. `src/lib/version.ts` 的 `PRODUCT_VERSION`
3. 落地页徽章文案（`src/components/landing/hero.tsx` 的版本行 + 本版主更新）
4. `src/components/landing/whats-new.tsx` 的 FEED 增加本版条目
5. README 的版本 / 变更说明
6. 跑 `bun run lint`、`bun run test`、`bun run build` 三道门禁
7. 验证版本同步守卫测试通过（`src/lib/version.test.ts`）

> 守卫测试是硬约束：任何一处漏改，`bun run test` 会失败，不允许绕过。

### 4.3 本版版本号

当前版本定为 **0.2.0**（仓库原 `package.json` 为 `0.1.0`，无既有发布版本号语义，取次版本号）。
