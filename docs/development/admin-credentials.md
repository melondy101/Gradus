# 管理员凭据配置与更换

管理员登录由服务端环境变量管理，不使用公开注册或普通账号的邮箱绑定、密码恢复流程。

```dotenv
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=使用独立强密码
ADMIN_USER_ID=原管理员账号的用户ID
NEXT_PUBLIC_ADMIN_EMAIL=admin@example.com
```

`ADMIN_USER_ID` 固定数据库中的原账号身份。任务、通知、头像、观猹绑定及其他账号资料继续属于同一个用户 ID，不进行账号合并。它是服务端变量，不要新增公开版本。

## 已有账号第一次配置

1. 在已登录管理员的浏览器打开 `/api/auth/me`，读取返回的 `user.id`。
2. 将此 ID 写入部署环境的 `ADMIN_USER_ID`，保持邮箱、密码不变并重新部署。
3. 重新登录。升级前签发的管理员会话会要求重新登录。

新实例未设置 ID 时，首次管理员登录创建 `admin-system-root`。旧实例未设置 ID 时，仍支持按当前管理员邮箱找到原账号；旧账号更换邮箱前必须先固定 ID，不能依赖新邮箱推断旧身份。

## 修改邮箱或密码

保持 `ADMIN_USER_ID` 不变，修改 `ADMIN_EMAIL` 或 `ADMIN_PASSWORD`。改邮箱时同步修改前端的 `NEXT_PUBLIC_ADMIN_EMAIL`。重新部署并停用旧版本实例，再使用新邮箱、新密码登录。

新版本实例在每次认证时核对管理员会话与当前凭据配置，旧会话无需等到再次登录就会被拒绝。首次使用新凭据登录时，在事务内更新原账号邮箱/密码并递增会话版本；正常重复登录不递增版本。仅修改前端展示变量不会撤销会话。

已经绑定观猹的管理员仍可通过观猹重新认证，登录时同步当前配置。旧会话不能用于新增观猹绑定；更换环境密码不会解除已有观猹绑定。

新邮箱若已属于其他账号，登录返回冲突，不会合并、覆盖或接管该账号。配置的用户 ID 不存在时也会拒绝初始化；先核对 ID，不要通过改成别人的 ID 来处理邮箱冲突。

不要把真实密码写入此文档或提交仓库。修改环境配置后，旧部署若仍在接收请求，会继续按它的旧配置认证；必须完成部署切换。
